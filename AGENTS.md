# AGENTS.md

Instructions for coding agents working on mdmsign. Humans: read
[CONTRIBUTING.md](CONTRIBUTING.md), which has the full rules and reasoning.
This file is the short version of the parts agents most often get wrong.

mdmsign is a Rust CLI that signs, notarizes and verifies macOS `.pkg` files
and `.mobileconfig` profiles for MDM deployment. It handles signing
certificates and private keys, so the secret-handling rules below are hard
requirements, not style preferences.

## Layout

- `crates/mdmsign-core`: the library. All signing, verification and
  credential logic. Uses `thiserror`, never prints.
- `crates/mdmsign`: the binary. clap CLI (`cli.rs`), one module per
  subcommand (`commands/`), printing and exit codes (`output.rs`). Uses
  `anyhow`.

## Checks

Run all three before you say a change is done. CI runs the same commands on
Linux and macOS.

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --all-features --locked
```

`--all-features` is required: it turns on `mdmsign-core`'s `test-util`
feature, which the tests need.

## Secrets and signing material

- Never create, commit or ask for real certificates, `.p12`/`.p8` files or
  passwords. Tests generate throwaway identities with
  `mdmsign_core::testutil::TestIdentity::generate(CertKind::…)`.
- Wrap passwords and private keys in `Secret`. Call `expose()` only where the
  value is consumed.
- Never pass a secret to an external tool as a command-line argument: other
  processes can read it (see `tool.rs`).
- Never put tool output in an error message if it could echo a secret.
- When a test passes a password or key, also assert it doesn't appear in
  stdout or stderr.
- Text that comes from the files being processed (certificate names, tool
  output) must go through `output::clean` (or `clean_line`) before it's printed.

## Errors

- Every error says what went wrong (`#[error("…")]`: lowercase, no trailing
  period, names the file/certificate/variable) and has a `hint()` that says
  how to fix it, naming the exact flag, variable or command.
- Add errors to the owning area's enum (`CredentialError`, `PkgError`, …).
- Usage and credential problems exit 2; keep `Error::is_usage_error` in sync.
  Everything else exits 1.
- In `verify`, every `Warn` or `Fail` check needs a `fix`. `CheckId`s are part
  of the `--json` contract; reuse existing ones where they fit.

## Tests

- Tests that call Apple's tools (`productsign`, `security`, `pkgutil`,
  `spctl`) go behind `#[cfg(target_os = "macos")]`.
- Tests that need a real certificate, the Keychain or Apple's notary service
  are `#[ignore = "needs …"]` and never run in CI.
- CLI tests clear every `MDMSIGN_*` variable and point `HOME` at a
  nonexistent directory. Copy that setup from `crates/mdmsign/tests/cli.rs`.
- Use `testutil::copy_fixture` for packages. Never modify the committed
  `tests/fixtures/unsigned.pkg`.

## Dependencies

- Declare dependencies once in the root `Cargo.toml` under
  `[workspace.dependencies]` with an exact `=` pin, and use
  `dep.workspace = true` in the crates. Prefer std and existing dependencies.
- `apple-codesign`, `apple-xar`, `cryptographic-message-syntax`,
  `x509-certificate` and `bcder` must stay on the versions `apple-codesign`
  uses. Don't bump one on its own.
- Don't add `deny.toml` advisory ignores without a reason mdmsign isn't
  affected.

## Docs and release files

- Update `CHANGELOG.md` under **Unreleased** for anything a user would
  notice, and the README if flags, output or behavior change.
- `.github/workflows/release.yml` is generated by dist. Don't edit it by
  hand: change `dist-workspace.toml` and run `dist generate`.
